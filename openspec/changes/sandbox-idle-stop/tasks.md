## 1. The activity record and the idle rule (`src/idlestop.ts`, pure, tested)

- [ ] 1.1 `SandboxActivity` per design D3/D6, with an injectable clock: `start()` sets the floor of every last-activity value; `touch(name)`; `track(name, op)` counts the call in flight and touches at its start and end (also when `op` rejects); `markStopped(name)` and `clearStopped(name)` (only a successful warm-up clears the mark: nothing else can start a stopped container); `view(name)` → `{ lastActivity, inFlight, stopped }`; `exclusive(name, fn)`, a per-name promise-chain lock that a rejected `fn` never breaks. One module-level instance (`sandboxActivity`) for the driver. Verify: `node --import tsx --test src/idlestop.test.ts` — floor before any touch, in-flight back to 0 after a rejecting op, the mark kept across touches and cleared by `clearStopped`, two `exclusive` sections on one name never overlap while two names run in parallel.
- [ ] 1.2 `idleStopDue(inputs)` per D2 → `{ stop: false } | { stop: true, forced?: 'background' | 'injected' | 'call' }`: off when `autoStopMinutes ≤ 0` or the container is marked stopped; never while held; quiet time against `autoStopMinutes`; lingering work (the engine's `lingering`, `inFlight > 0`) postpones until `max(autoStop, hardCap)`. Verify: `src/idlestop.test.ts`, one case per scenario of the spec's *An idle project container is stopped*, *Turns hold the container whatever their silence* and *Lingering work postpones the stop up to the turn hard cap* (30 min idle → stop; 29 → not; held at 45 min → not; background at 40 → not, at 61 → stop with `forced: 'background'`; a call in flight at 61 → `forced: 'call'`; `0` and `-5` → never).
- [ ] 1.3 `idleSweepTick(deps)` per D5, with every dependency injected (projects with their container names, a driver per kind, the engine view, the record, clock, log): nothing due → no `listStates`; a candidate not `started` → marked stopped, no stop call; a running candidate → `stopSandbox(name, slug, recheck)` whose `recheck` evaluates D2 again on fresh inputs; outcome `stopped` → `sandboxStopped(slug)` and the mark; `foreign …` → one warning per name per process; a thrown or failed stop → `idle stop of '<name>' failed: …` warning, nothing marked, sessions untouched; a driver without `stopSandbox` (Daytona) or one whose construction throws (one warning) → skipped. The log lines are exactly D5's. Verify: `src/idlestop.test.ts` with fakes, covering each spec scenario of *A stop and a wake never interleave* that the tick owns (work queued between the first check and the stop → no stop), *Only this installation's containers are stopped* and *Configuration and where the stop runs* (unreachable host → warning, retried next tick).
